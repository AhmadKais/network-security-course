  • תוקף ברשת המקומית פועל מתחת להם

המתג "בוטח" בכל מה שמחובר אליו כברירת מחדל – זו הבעיה. סיפור השקע ממחיש.

MAC Overflow ו-Port Security

  • טבלת MAC מוגבלת; תוקף מציף אלפי MAC מזויפים
  • המתג עובר ל-fail-open = משדר הכול לכולם (כמו hub)
S1(config-if)# switchport mode access
S1(config-if)# switchport port-security
S1(config-if)# switchport port-security maximum 2
S1(config-if)# switchport port-security violation shutdown
נשאל בבגרות. הדגישו: חובה mode access קודם. violation shutdown = err-disabled.

VLAN Hopping

  • Switch spoofing – מחשב מתחזה למתג עם DTP, מקבל trunk = כל ה-VLANים
  • Double tagging – שני תגים, מנצל את ה-native VLAN
S1(config-if)# switchport mode access
S1(config-if)# switchport nonegotiate   ! כיבוי DTP
S1(config-if)# switchport trunk native vlan 999
נשאל בבגרות: השבתת DTP מונעת VLAN hopping. native VLAN ייעודי נגד double tagging.

STP – למה צריך אותו

  • מסגרת שכבה 2 אין לה TTL
  • לולאה פיזית ⇒ broadcast storm ⇒ הרשת קורסת בשניות
  • STP חוסם פורטים לוגית להשארת מסלול יחיד
בבגרותSTP פועל בשכבה 2, מונע לולאות ע"י חסימת יציאות (port blocking)
הנקודה המרכזית: אין TTL בשכבה 2, לכן לולאה = אסון. STP חוסם פורט אחד.

שאלת בגרות: מי ה-root?

4 מתגים, priority זהה (default). MAC: SW1=...22..., SW4=...1A... מי ה-root bridge?

SW4 – priority זהה ⇒ מכריע ה-MAC הנמוך ביותר. 1A < 22.
Bridge ID = priority + MAC. priority שווה ⇒ MAC נמוך מנצח. שאלה 3ז מהבגרות.

הגנות STP

S1(config-if)# spanning-tree portfast
S1(config-if)# spanning-tree bpduguard enable
! גלובלי (התשובה בבגרות):
S1(config)# spanning-tree portfast bpduguard default
  • BPDU Guard – פורט קצה שמקבל BPDU ⇒ err-disable
  • Root Guard – מונע ממתג להפוך ל-root
נשאל בבגרות – הפקודה הגלובלית. BPDU Guard מגן מפני מתג/תוקף שמחובר לפורט משתמש.

DHCP Snooping ו-DAI

  • rogue DHCP – שרת תוקף מחלק gateway/DNS שלו = MITM
  • DHCP Snooping – פורטים trusted/untrusted; בונה טבלת binding
  • DAI – בודק ARP מול הטבלה; מזייף נחסם
S1(config)# ip dhcp snooping
S1(config-if)# ip dhcp snooping trust   ! לכיוון השרת
S1(config)# ip arp inspection vlan 10
DAI מסתמך על טבלת ה-snooping. rogue DHCP הוא דרך נפוצה מאוד ל-MITM.

SPAN – החיבור ל-IDS

  • SPAN = שיקוף פורט (port mirroring)
  • מעתיק תעבורה לפורט שאליו מחובר IDS/Wireshark
S1(config)# monitor session 1 source interface f0/1 - 10
S1(config)# monitor session 1 destination interface f0/24

כך IDS "מחוץ לנתיב" (פרק 5) מקבל תעבורה

קושר לפרק 5. גם storm-control מזכירים כאן (הגנה מ-broadcast storm).

שאלת בגרות: Evil Twin

מהם מתכנני התקפת Evil Twin?

לשתול נקודת גישה זדונית עם SSID זהה לנקודה חוקית, לצורך גניבת מידע (MITM).
הגנה: WPA2/3-Enterprise (802.1X – אימות הדדי, המכשיר מוודא את השרת). מקשר לפרק 3.

עוד: NAC · IronPort · VoIP · SAN

  • NAC – בודק "בריאות" מכשיר לפני גישה (על 802.1X)
  • IronPort – אבטחת מייל (ESA) ו-web (WSA)
  • VoIP – voice VLAN נפרד, SRTP
  • SAN – zoning, LUN masking
סקירה קצרה – אלה נושאים משלימים בתכנית. NAC מקשר לפרק 3 (802.1X).
