חומות אש ו-ACL

ACL סטנדרטי/מורחב · wildcard · מיקום וכיוון · CBAC · ZPF
אבטחת מידע · מגמת תקשוב
היום הכלי הכי בסיסי ונשאל בקורס – ACL. פתחו Packet Tracer. זה פרק שדורש הרבה תרגול ידיים.

מהי חומת אש

  • עומדת בין רשתות ברמות אמון שונות
  • כל התעבורה עוברת דרכה (נקודת מעבר יחידה)
  • מחליטה permit/deny לפי מדיניות
הקזינו והאקווריום (2017)נפרצו דרך חיישן טמפרטורה חכם – כי לא היה ACL שמפריד אותו משאר הרשת
חומת אש היא לא רק בין "פנים" ל"אינטרנט" – גם בין חלקי הפנים (פילוח). סיפור האקווריום ממחיש.

סוגי חומות אש

ACL הוא stateless – זה מה שנלמד קודם. Stateful (ZPF/CBAC) בהמשך הפרק.

ACL – שלושה חוקי ברזל

  1. נסרקת מלמעלה למטה
  2. עוצרת בהתאמה הראשונה
  3. בסוף יש deny any סמוי (implicit deny)
מסקנהסדר השורות קריטי · חייבים permit מפורש אחרת הכול נחסם
שלושת החוקים מסבירים 90% מהטעויות. חזרו עליהם בכל תרגיל.

Wildcard Mask

wildcard = 255.255.255.255 − subnet mask

רשתWildcard
/240.0.0.255
/280.0.0.15
מארח בודד0.0.0.0 = host
כל כתובת255.255.255.255 = any
ביט 0 = חייב להתאים · ביט 1 = לא אכפתהפוך מ-subnet mask!
הנקודה שהכי מבלבלת. תרגלו המרות על הלוח. הנוסחה 255-mask היא הדרך המהירה.

כלל המיקום נשאל! סטנדרטי בודק רק מקור, לכן קרוב ליעד כדי לא לחסום יותר מדי.

ACL מורחב – דוגמאות

access-list 101 deny ip 172.18.1.0 0.0.0.255 host 10.0.0.190
access-list 101 permit ip any any
interface g0/0
 ip access-group 101 in

access-list 110 permit tcp any any eq 443
access-list 110 deny icmp any any echo    ! חסימת ping
שאלה זו בדיוק בבגרות (IT מקבל DNS/DHCP אך לא WEB). הדגישו את השורה permit בסוף.

כיוון: in או out?

  • in = נכנס לנתב דרך הממשק (לפני ניתוב)
  • out = יוצא מהנתב דרך הממשק (אחרי ניתוב)
מנקודת מבט הנתב, לא המשתמשACL אחת לכל ממשק, לכל כיוון
ציירו נתב עם חצים. תלמידים מתבלבלים – "out" זה החוצה מהנתב לרשת, לא החוצה מהרשת.

שאלת בגרות

R1: G0/0→רשת1, G0/1→רשת2, G0/2→רשת3 (מוגבלת). לחסום רשת2 מרשת3 בלבד. איפה וכיוון?

ACL סטנדרטי ⇒ קרוב ליעד ⇒ G0/2 out. סדר: deny 192.168.2.0 ואז permit any. (in על G0/1 היה חוסם גם לרשת1 ולאינטרנט!)
שאלה 7ה מהבגרות. עברו לאט. הדגישו למה in על G0/1 שגוי.

ACL נגד התקפות (anti-spoofing)

! כתובות פרטיות לא אמורות להגיע מהאינטרנט
deny ip 10.0.0.0 0.255.255.255 any
deny ip 192.168.0.0 0.0.255.255 any
deny icmp any any echo        ! נגד ping sweep/Smurf
permit tcp any any established ! רק תשובות
מקשר לפרק 1 (spoofing, Smurf). מסנן בכניסה מהאינטרנט. established = "stateful לעניים".

מ-ACL ל-Stateful: CBAC ו-ZPF

  • CBAC – בוחן תעבורה יוצאת, פותח אוטומטית חור לתשובות
  • ZPF – הגישה המודרנית: אזורים + מדיניות בין זוגות
ZPF – חוקי ברזלאותו אזור=מותר · אזור↔לא-אזור=חסום · בין אזורים=חסום עד zone-pair
ACL הוא stateless וצריך לפתוח פורטים ידנית לתשובות. Stateful פותר את זה אוטומטית.

ZPF – 5 שלבים

1. zone security INSIDE / OUTSIDE
2. class-map type inspect  (איזו תעבורה)
3. policy-map type inspect (inspect/pass/drop)
4. zone-pair security      (מקור→יעד + policy)
5. zone-member security    (שיוך ממשקים)
3 פעולותinspect=stateful (תשובות אוטומטית) · pass=כיוון אחד · drop=חסום
inspect הוא מה שרוצים כמעט תמיד – הוא מטפל בתשובות. pass לא. הסדר של 5 השלבים חשוב.

שאלה

ב-ZPF, G0/0 באזור INSIDE ו-G0/1 לא שויך לאף אזור. מה קורה לתעבורה ביניהם?

נחסמת. ממשק באזור לא מתקשר עם ממשק שאינו באזור.
חוק ברזל של ZPF. טעות נפוצה – שוכחים לשייך ממשק.
