פרק 2
אבטחת אביזרי רשת

הקשחת נתב · SSH · syslog · NTP · SNMP · AutoSecure
אבטחת מידע · מגמת תקשוב
מהתיאוריה למעשה. היום מלכלכים ידיים: איך הופכים נתב "פתוח" לנתב מאובטח. פתחו Packet Tracer במקביל אם אפשר.

מה נלמד היום

  • למה דווקא הנתב הוא המטרה הראשונה של תוקפים
  • איך בכלל מדברים עם נתב (CLI ומצבי עבודה)
  • סיסמאות: מה חזק, מה חלש, ולמה
  • Telnet מול SSH – ההבדל שמציל אתכם
  • יומנים (syslog), זמן (NTP), ניטור (SNMP)
  • כיבוי שירותים מיותרים ו-AutoSecure
מפת השיעור. הבטיחו הרבה פקודות אמיתיות + סיפורים על נתבים שנפרצו.

חלק א'
למה הנתב הוא מטרה?

רקע: מה זה בכלל נתב, ומה יש בו

  • נתב (Router) – מעביר תעבורה בין רשתות (הבית ↔ האינטרנט). "צומת הדרכים"
  • נתב קצה (Edge router) – הנקודה שבה הרשת שלכם פוגשת את העולם
  • מי ששולט בנתב יכול: לראות את כל התעבורה, לחסום, להטות, לפתוח דלת פנימה
3 תחומי הגנה על נתבפיזי (מי ניגש אליו) · מערכת ההפעלה (גרסה, גיבוי) · הקשחה (הגדרות)
הדגישו: הנתב הוא "השומר בשער". אם הוא נפרץ – כל השאר לא משנה. תכף נראה דוגמה אמיתית.

מהעולם האמיתי: 500,000 נתבים ביתיים נחטפו (VPNFilter, 2018)

  • נוזקה בשם VPNFilter הדביקה מעל חצי מיליון נתבים ביתיים וקטנים בעולם
  • היכולות: ריגול אחר התעבורה, גניבת סיסמאות, ואף "הריגת" הנתב (bricking)
  • ה-FBI ייחס אותה לתקיפה מדינתית והשתלט על שרת השליטה שלה
  • איך נכנסה? חולשות ידועות + סיסמאות ברירת מחדל שלא שונו
הלקחהנתב הוא מחשב לכל דבר – ואם לא מקשיחים אותו, הוא הדלת הכי קלה פנימה
סיפור פתיחה חזק. שאלו: כמה מכם יודעים מה דגם הראוטר בבית ומתי עודכן לאחרונה? כמעט אף אחד – וזו בדיוק הבעיה.

חלק ב'
איך מדברים עם נתב?

רקע: CLI ומצבי עבודה

  • CLI – שורת פקודה. מקלידים טקסט, אין עכבר. כך מנהלים ציוד סיסקו
  • IOS – מערכת ההפעלה של הנתב (כמו Windows, אבל לנתב)
מה שרואיםאיפה אנימה מותר
R1>Userרק להסתכל
R1#מנהל (enable)הכול
R1(config)#הגדרותלשנות תצורה
R1(config-if)#ממשק אחדלהגדיר פורט
זו התשובה לשאלה "מה זה R1(config)": R1=שם הנתב, בסוגריים=באיזה חלק אני, > או # = רק להסתכל או מותר לשנות. הדגימו את המעבר בין המצבים בשקף הבא.

"סיפור" של פקודות – קראו את הפרומפט

R1> enable                 ! מ"רק להסתכל" ל"מנהל"
R1# configure terminal     ! נכנסים למצב הגדרות
R1(config)# hostname R1    ! נותנים שם לנתב
R1(config)# interface g0/0 ! נכנסים לפורט מסוים
R1(config-if)# no shutdown ! מדליקים אותו
R1(config-if)# end
R1# write                  ! שומרים!
זכרוהפרומפט תמיד אומר לכם איפה אתם. הלכתם לאיבוד? הקלידו end כדי לחזור למעלה
קראו את זה בקול כמו סיפור. הדגישו את ההבדל בין running-config (בזיכרון) ל-startup-config (שמור) – write שומר.

חלק ג'
סיסמאות והקשחה

סיסמאות – secret מנצח password

R1(config)# enable secret Str0ng-P@ss   ! מגובב – בטוח
R1(config)# enable password weak         ! גלוי – לא!
R1(config)# service password-encryption  ! מסתיר סיסמאות בקונפיג
R1(config)# username admin secret P@ss
  • password = טקסט גלוי / הצפנה חלשה (type 7) – נשבר בשנייה באתר אונליין
  • secret = גיבוב חד-כיווני – לא ניתן לשחזר ✓
הדגישו: service password-encryption מגן רק מפני הצצה מעבר לכתף. secret הוא ההגנה האמיתית.

שאלה לכיתה

מה ההבדל בין enable password ל-enable secret?
איזה תבחרו ולמה?

secret נשמר כגיבוב חד-כיווני (אי אפשר לשחזר). password נשמר גלוי/type 7 (נשבר מיד). תמיד secret.
תנו לכיתה לענות. אם מגדירים את שניהם – ה-secret גובר וה-IOS מתעלם מ-password.

מהעולם האמיתי: Telnet שנלכד בבית חולים

  • בבדיקת חדירה, הבודק חיבר מחשב לשקע רשת בחדר המתנה והריץ Wireshark
  • תוך 40 דקות לכד session של Telnet של טכנאי שהתחבר למתג הראשי
  • שם המשתמש והסיסמה עברו בטקסט גלוי – השתקפו על המסך
  • עם הסיסמה הזו – שליטה בכל המתגים בבניין
הלקחTelnet שולח הכול גלוי. הפתרון: שורה אחת – transport input ssh
ממחיש בדיוק למה Telnet מסוכן. תכף נראה איך מגדירים SSH במקומו.

Telnet מול SSH

Telnet (23)הכול בטקסט גלוי – כל מאזין רואה שם וסיסמה
SSH (22)הכול מוצפן + אימות השרת. גרסה 2 בלבד
מקלידים סיסמה→ SSH מצפין →ג'יבריש ברשת→הנתב מפענח
הדגמה מנצחת אם יש זמן: לכדו Telnet ב-Wireshark, הראו את הסיסמה. זו הצצה לפרק 7 (הצפנה א-סימטרית עם מפתחות RSA).

הגדרת SSH – 5 שלבים

R1(config)# hostname R1
R1(config)# ip domain-name school.local
R1(config)# crypto key generate rsa modulus 2048
R1(config)# username admin privilege 15 secret P@ss
R1(config)# ip ssh version 2
R1(config)# line vty 0 4
R1(config-line)# login local
R1(config-line)# transport input ssh   ! חוסם Telnet
חובה לפני crypto keyhostname + ip domain-name – אחרת: "Please define a domain-name first"
הריצו בעצמכם קודם. הטעות מספר 1: שוכחים domain-name. הראו ש-Telnet נכשל אחרי transport input ssh.

תרגיל – סדרו את הפקודות

לפניכם פקודות בערבוב. באיזה סדר צריך להריץ כדי ש-SSH יעבוד?

crypto key generate rsa · login local · hostname R1
transport input ssh · ip domain-name lab.local · line vty 0 4
hostname R1 → ip domain-name lab.local → crypto key generate rsa → line vty 0 4 → login local → transport input ssh. (השם והדומיין חייבים לפני יצירת המפתחות.)
תרגיל מצוין. הנקודה: המפתחות נגזרים מ-hostname+domain, אז הם חייבים לבוא ראשונים.

שאלה: login מול login local

מה ההבדל, ולמה SSH דורש דווקא login local?

login = מבקש רק סיסמה של הקו (בלי שם משתמש). login local = מבקש שם משתמש + סיסמה מהמסד המקומי. SSH דורש שם משתמש – ולכן חייב login local.
נשאל בבגרות (שאלה 2א – התשובה הנכונה כללה username + login local).

Banner – אזהרה משפטית

R1(config)# banner motd #
*** גישה בלתי מורשית אסורה. הפעילות מנוטרת ומתועדת. ***
#
מה לא לכתובלא "Welcome" (בבית משפט בארה"ב פורץ טען שהוזמן!), לא שם החברה, לא דגם הנתב
הבאנר הוא ההגנה המשפטית. הרעיון: להבהיר שהגישה אסורה ומנוטרת – לא להזמין. סיפור ה-"Welcome" ממחיש למה.

מהעולם האמיתי: הדגל האמריקאי על 168,000 נתבים (2018)

  • קבוצת האקרים ניצלה שירות ניהול פתוח (Cisco Smart Install) שנחשף לאינטרנט
  • הם מצאו את הנתבים החשופים דרך מנוע החיפוש Shodan
  • איפסו את הקונפיג של ~168,000 נתבים והשאירו הודעה: דגל אמריקאי + "אל תתעסקו עם הבחירות שלנו"
  • נפגעו ספקיות אינטרנט באיראן וברוסיה
הלקחשירות ניהול מיותר שנשאר פתוח = הזמנה. כבו כל מה שלא צריך
סיפור אמיתי ומצוין. מקשר ישירות ל"כיבוי שירותים" וגם ל-Shodan (שקף בהמשך). Cisco Smart Install היה שירות שאף אחד לא ידע שהוא פתוח.

חלק ד'
ניטור: לדעת מה קורה

Syslog – יומן האירועים

  • הנתב מייצר הודעות: ממשק עלה/נפל, כניסה כושלת, ACL שחסם
  • שולחים אותן לשרת syslog מרכזי – שנשמר גם אם הנתב נפרץ או אופס
R1(config)# logging host 10.0.0.5
R1(config)# logging trap warnings   ! רמות 0–4
8 רמות חומרה0=Emergency (החמור) … 7=Debug. בוחרים רמה ומקבלים אותה וכל מה שחמור ממנה
למה מרכזי? כי תוקף חכם מוחק את הלוגים המקומיים. שרת חיצוני שומר את הראיות. נשאל בבגרות (פקודת logging).

NTP – למה זמן מדויק זה אבטחה

  • בלי זמן מסונכרן, אי אפשר לשחזר סדר אירועים בין הנתב, חומת האש והשרת
  • "הכניסה הכושלת בנתב הייתה לפני או אחרי החדירה לשרת?" – בלי NTP לא תדעו
  • גם תעודות דיגיטליות ומפתחות VPN תלויים בזמן נכון
R1(config)# ntp server 10.0.0.5
אנלוגיה: חקירה משטרתית בלי חותמות זמן על מצלמות האבטחה – אי אפשר להרכיב את הרצף.

SNMP – ניטור ציוד

גרסהאימותהצפנה
v1 / v2c"community" גלוי ("public")אין ✗
v3שם + HMACכן ✓
מהעולם האמיתימנוע החיפוש Shodan מוצא עשרות אלפי מכשירים עם SNMP "public" חשוף – כל אחד יכול לקרוא מהם מידע. תמיד v3
Shodan = "גוגל של מכשירים מחוברים לאינטרנט". חפשו איתו בכיתה (בזהירות) "default password" ותראו כמה מכשירים חשופים. ממחיש הכול.

כיבוי שירותים ו-AutoSecure

R1(config)# no ip http server      ! ממשק web מיותר
R1(config)# no cdp run             ! חושף דגם ו-IOS לשכנים
R1# auto secure                  ! הקשחה בפקודה אחת
זהירות עם AutoSecureהוא "עיוור" – עלול לכבות דברים שצריך. הריצו, בדקו עם show auto secure config, וכווננו
כל שירות פתוח = דלת אפשרית (זכרו את סיפור Cisco Smart Install!). כלל: אם לא צריך – כבה.

שאלת בגרות

מנהל הפיק מפתחות RSA בנתב. מה ניתן לעשות איתם?

  • 1. רק אחרי איפוס, ל-SSH
  • 2. ל-SSH
  • 3. רק אחרי איפוס, ל-Telnet
  • 4. ל-Telnet
2 – ל-SSH (ללא איפוס). Telnet לא משתמש במפתחות כלל.
שאלה אמיתית (5ב). מקשר את הפרק לפרק 7 (הצפנה).

תרגיל – מצאו את הבעיות בקונפיג

Router(config)# enable password cisco
Router(config)# line vty 0 4
Router(config-line)# password cisco
Router(config-line)# transport input telnet
Router(config)# banner motd # Welcome to ACME Corp! #
1. enable password (גלוי) במקום secret. 2. סיסמה חלשה "cisco". 3. אין שם משתמש (חסר login local). 4. transport input telnet – לא מוצפן, צריך ssh. 5. באנר "Welcome" + שם החברה. 6. השם נשאר "Router" (ובלי domain-name אין SSH).
תרגיל סיכום מצוין. תנו לכיתה לצוד באגים לפני שחושפים. כל באג מדגים עיקרון שלמדנו.

מהעולם האמיתי: Shodan – "גוגל של המכשירים"

  • מנוע חיפוש שסורק את כל האינטרנט ומקטלג מכשירים חשופים
  • אפשר לחפש: ראוטרים, מצלמות, בקרים תעשייתיים – רבים עם סיסמת ברירת מחדל
  • תוקפים משתמשים בו לסיור (פרק 1); מגנים – כדי לגלות מה הם חושפים
משימה למורה (הדגמה)הראו את shodan.io בכיתה – ממחיש למה הקשחה קריטית
חיבור יפה בין פרק 1 (סיור) לפרק 2 (הקשחה). כל מה שהקשחנו היום מוריד אתכם מהרשימה של Shodan.

סיכום פרק 2

  • enable secret, לא password
  • SSH בלבד ל-VTY (login local + transport input ssh)
  • syslog + NTP מרכזיים – לניטור ולשחזור
  • SNMPv3, כיבוי שירותים מיותרים, AutoSecure
  • כל שירות פתוח = דלת. אם לא צריך – כבה
הרעיון המרכזיהנתב הוא השומר בשער – והקשחה הופכת אותו משער פתוח לשער נעול
חזרה. מעבדה: הקשחת נתב מלאה ב-Packet Tracer (SSH, login block, syslog, NTP).
